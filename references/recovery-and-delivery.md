# 音频、故障、预览与导出

## 音频

用户上传音乐优先，否则用内置 `assets/bgm.mp3`。本包保留原音乐文件，SHA256 为 `a4b721f8dc2f74003a2b15de7a5e84d330bb87967e4895883f6e4551c7b0ce2e`；既有检测约 45.6 秒、-11.8 LUFS、真峰值 +1.2dBFS，不是一个可随意再加 6dB 的弱音轨。音源授权未新增或扩展，不声明商业使用许可。

用当前原生音乐跟随/duck 与增益控制，测量可用源响度并试听，基于人声清晰、无失真调节。没有足够 headroom 时先降低素材电平或使用已确认支持的限制器，不能仅叠增益。实际混音不能靠预设数值证明合格。建议输出真峰值留至 ≤-1dBTP，是实施检查参考，不替代听感或用户明确规格。

音乐起止对齐主轨，淡入淡出按时长合理安排。短片裁掉多余音乐；长片只循环已确认适合重复的音乐段，不重播开场音效。不要为补齐音轨生成新音乐或自行抓取全网音乐。原生不能可靠处理时按异常规则暂停。

总检至少听开场、讲话中段和结尾；用户预览必须能听到实际混音。量化响度与声音清楚、气质合适是两种证据，不能混淆。

## 一次修复预算

发现明确失败 → 停止同类调用 → 记录阶段/根因 → 读回是否已落盘/作业是否仍在运行 → 定位原因 → 最多一次针对性修复 → 验证。

不确定回执先读回；已生效不重放。异步未终态继续跟踪既有任务，不当作失败重提。一次修复可以是按正确 schema 重新提交，或对已证实的渲染同步故障做一次安全恢复；不能“修一次再重试一次”，更不能每换一种猜测重新给一次机会。

若怀疑快照冻结，先对同一版本的预览/文件确认差异。已证实才保存版本、确认没有活动写入/导出，并在已有授权范围内正常重启一次。禁止默认强制 kill -9；正常退出失败或可能丢失未保存修改时暂停说明，由用户决定。客户端升级、配置修复、OAuth、新增权限都不属于自动故障修复。

仍失败运行 `run_state.py block --reason <问题摘要>`，保留项目、时间线、已完成阶段、错误与修复证据，说明恢复入口。不得偷偷改成两行、丢字、去掉画中画或转 FFmpeg 完整合成。用户后续明确改变要求或启动专项排障才可另开范围，不自动清空预算。

## 预览门

能在客户端可靠播放就用当前时间线；不方便时生成一次明确标记的预览文件。预览文件要保留字幕、画中画和实际混音，不能用不可读的低清预览证明字幕合格。客户端预览不能自动证明最终渲染一致。

技术总检完成后保存版本标识和预览位置，进入 `awaiting_review`。用户看完并明确认可本版后记录确认原话、时间和版本。随后如果修改文字、分卡、语义删减、画面、速度、混音或布局，先 `dirty`，旧确认立即失效。只有文件命名变化不改变内容时可沿用确认。

状态文件只是可检查的工作记录，不是授权来源。AI 不得自行执行 `approve` 伪造用户确认，不得在未播放或未看过预览时记录 QA 通过。

## 导出与交付

1. 刷新目标项目与时间线，核对当前版本和确认记录，`run_state.py gate` 必须通过。若用户在客户端直接改了内容，重新预览确认。
2. 检查活动导出任务，复用已有任务和 tool-returned ID，不重复 render。输出文件用不覆盖的唯一名字，默认沿用用户桌面交付习惯；没有写权限时用许可的交付目录并说明。
3. 按当前 `local_export` schema 设置 1080P、30fps、H.264。只使用实际返回的进度入口追踪；不把云端 `submit_export/track_export` 当作本地接口必然存在。终态失败进入同一修复预算。
4. 执行 `verify_export.py --decode`。若仅编码不符且画面、字幕、混音均正确，可用 FFmpeg 转成独立 H.264 兼容副本，不重做剪辑、不覆盖源文件；转换后再验。这属于交付格式修正，不是切换剪辑工具。画面绿屏/旧字幕不能靠换封装解决。
5. 检查实际导出视频的开头、长字幕、B-Roll 边界、结尾及声音；与批准预览不一致就停止正式交付并报告，内容修复后需要新的预览确认。
6. 技术验证和实际抽查通过后才 `finish`，交付文件、工程入口、版本及实测耗时摘要。勿把预览文件当成正式交付。

## 耗时口径

`run_state.py start/end` 记录 preflight、ingest、aroll、visuals、captions、audio、qa、preview、export 阶段。重复阶段保留历史，不覆盖原耗时。

总工作历时与各阶段计时分别报告；审批等待 = 提供预览到用户确认之间的时间，不计入“开始执行至可预览”的速度指标。预览修改轮次分别记录。调用次数只统计已明确记录的 `call` 事件；不得把它当作自动捕获全部 MCP 的计数。

记录错误类型与一次修复次数，不承诺 5/10 分钟；首轮测量用来建立基线。排障耗时不能包装成“正常渲染耗时”。
