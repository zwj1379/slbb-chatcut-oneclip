# 字幕准确性、分卡与安全区

## 验收边界

用户已确认：以实际口播为准，用文案辅助校正；样式可变，准确、完整、显眼、每卡最多两行、整卡不越安全边距不可变。单行优先，两行可接受（2026-10-09 用户更新，原「严格单行」限制取消）。没有要求必须黑底白字、去标点、得意黑或固定模板。

发布平台规避词是字幕完整性的明确显示例外（2026-10-15 用户更新）：用户指定或高置信的品牌、同行、产品专名在实际口播中照常保留，但其对应时间段的可见字幕留白。不得用“某工具”等词改写台词，也不得修改源转写、音频或主轨剪辑来制造留白。

文案对照只修识别错误，不替换口播真实意思。不能将口播省略、改说或根本未说的句子补进字幕。专名、金额、数字、否定词以及影响意思的同音词重点核对。没有文案时仍可依据实际音频校对；听不清且影响意思则标注并暂停解决，不编造。

## 原生能力优先

1. 显式把主口播轨设为唯一字幕来源；B-Roll、真人小窗不参与。
2. 集中核对文字和实际语音，形成语义分卡计划，保留词级时间。
3. 用当前原生分页/卡片拆分/文本纠正能力落实计划。工具接受 token 边界时按最新真实词键拆分，不能凭字符下标猜边界。`split_card` 的实测契约（Desktop 0.5.16）：参数名是 `beforeTokenId`；取值来自 `read_captions words=true`，且必须是**去掉 `<cardId>:` 前缀的纯 token UUID**。传 `beforeWordKey`、空值或已失效的 token 会报 `beforeTokenId must be a non-empty string`；传带卡片前缀的完整 id 会报 `Caption split boundary is invalid`。一次只切一个边界，切下一张前重新读回最新 token 与 card id。
4. 选择一种可读且支持所需布局的模板，应用一次；最后设布局。如模板自动重建卡片，重新读当前 card ID 与 revision，只修受影响卡片。
5. 验证全部卡片的内容、时段、行数（每卡不超过两行）与安全区，再看长句、数字、英文词和相邻卡交界的代表帧。镜头或背景明暗变化处检查可读性。

当前指南说明字幕 Content 面板的搜索替换与分合卡在 Web 和 Desktop 0.2.25+ 可用，但 UI 能力不证明当前 MCP 已暴露对应接口；运行时必须核验版本及 schema。

## 平台规避词留白

1. 先完成主轨内容剪辑和普通字幕校对，再处理规避词，避免源轨变化使字幕卡重建。
2. 只匹配用户明确指定的词、明确别名及大小写/空格变体；未给清单时只把高置信品牌或产品专名列为候选，不把普通词或整句扩大删除。
3. 用 `read_captions words=true` 取得最新 token。先在目标词前分卡，重新读回；再在目标词后分卡，重新读回，使目标专名独占一张字幕卡。连续多个 token 构成同一名称时整体隔离。
4. 当前 schema 若有单卡删除或隐藏动作，删除目标词卡；该操作只能改变字幕程序，不得删除源视频、源音频或 Transcript 词。若 schema 没有该动作，停在已隔离的目标卡并让用户通过 Desktop Content 面板执行“删除字幕卡”，完成后读回验证。
5. 不得调用 `set_card_text` 写入空串、普通空格、全角空格、零宽字符或其它不可见 Unicode。它们可能被规范化为空值、破坏 token 绑定，或在不同字体/平台渲染为异常字符。
6. 不用中性词、星号、拼音或缩写代替，除非用户另行明确要求。默认结果就是该词时段没有可见文字。
7. 删除后全文搜索所有可见字幕，确认目标词及其别名均未显示；查看前一帧、目标词时段和后一帧，确认中间留白、前后字幕原文不变、音频连续。

该处理只控制画面字幕，不保证平台无法从音频识别相同词语，也不能表述为保证通过审核。

## 破坏性操作禁令

**不要对字幕 item 调用 `edit_captions action=style` 去改 `maxLines`（设 1 或设 2 都禁止），也不要借一次批量样式重写顺手完成分卡。** 该 action 会先套用可选 preset、再合并 item 级样式字段；Desktop 0.5.16 实测，仅为把 `maxLines` 设为 1，结果：

- 全部字幕 Card 被清空（`read_captions` 返回 0 张）；
- 素材转写被一并删除（`read_script` 返回 0 行，`manage_transcript` 报 `Transcribed Asset not found`）。

这不是“分卡没生效”，而是把已完成的字幕与转写一起推回起点，只能重跑语音识别才能恢复。行数由卡片宽度自然折行决定；`split_card` 只做语义断句，不是行数控制器（契约见上节第 3 条）。

`set_card_layout` 不是断行手段：它需要 `{"layout":{...}}` 包裹才不报错，但即使写入成功，画面仍可能按原有宽度折行。布局只用于安全区与宽度，不用于断句。

行数与安全区是否成立只看画面/渲染结果，不看接口是否返回成功。

## 分卡规则

优先按语义短句、自然停顿、并列项边界拆分；产品名、金额、英文短语、中文复合词不拆碎。每张卡对应真实已剪出的语音，使用主轨实际时间轴而非源文案字数平均分时。

检查相邻卡不会叠加、闪烁或把文字拖过对应语音。一行放得下时保持单行；放不下时允许自然折为两行，两行以**最长行**判宽，完整外接框（含背景、描边、动画极值）仍须落在安全区内。避免第二行只剩一两个字：优先按语义调整分卡边界，调不动则保留并记录，不改写文字。两行仍容纳不下的不可分词组，不裁字、不擅自改写；使用仍显眼的合适字号，仍放不下则报告例外。

`maxLines` 不是分卡也不是行数工具，任何取值都禁止写入（后果见上节「破坏性操作禁令」）。两行上限由本 Skill 规定、以画面实测为准，不用样式参数强制。禁止把溢出文字隐藏、删掉、裁掉或压成不可读的小字来“通过”。不要为了分字幕卡破坏主视频剪切结构。

## 安全区默认值（实施默认，不是平台保证）

用户未指定精确像素或发布平台，因此采用可调整的工程默认：左右各留画布宽度 10%，顶部留高度 5%，底部留高度 20%。1080×1920 时字幕完整外接框应位于 x=108…972、y=96…1536。包含描边、背景、阴影和动画极值；避免与右上角真人小窗重叠。

这组值是本优化版的保守起点，未获逐平台遮挡实测确认，不能声称抖音/视频号等平台一定无遮挡。用户指定平台或更大边距时更新并记录。总检要看实际像素，而非仅判断 API 写入成功。

优先在字幕轨/模板级统一设布局，不逐卡重复改样式。默认高对比文字，必要时描边或背景辅助；大小以手机可读为准，不为保持单行无限缩小，也不为把文字压进两行而缩到不可读。字体实际测量可辅助判断宽度，但字符数量阈值不是像素验收。

## 故障边界

“分卡边界 invalid”“样式数据正确但画面不变”“没有字幕”等按同一根因记录。第一次确认失败后读回当前状态，可针对最新 token、revision、模板布局或客户端同步做一次修复。修复后仍失败立即暂停并保存工程，不轮番换模板、调字号、切主视频、复制时间线或反复导出。

字幕阶段的任何读写前，先确认当前活动工程就是本任务工程。桌面端用户可随时切走；切走后 `read_captions` 会报 `The active Timeline has no caption model`。这是**假故障**，不代表字幕模型损坏，也不是进入恢复流程的理由——先用 `target_project` 切回目标工程再判断，切勿在错误工程上“修复”。

数据层完整而像素未验证，只能报告“文字结构已检查，渲染未验证”，不能称字幕合格。
